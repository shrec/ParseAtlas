## Ellipsoid, ზუსტად

WGS 84, მოცემული თავისი **ორი განმსაზღვრელი კონსტანტით**, საიდანაც დანარჩენი ყველაფერი ზუსტი rational-ის სახით გამოიყვანება და არა ციტირდება:

```text
a    = 6378137                        exact, defining
1/f  = 298.257223563                  exact, defining
f    = 1 / (1/f)                      exact rational
b    = a (1 - f)                      exact rational
e2   = f (2 - f)                      exact rational
```

*PRIOR ART.* გამოქვეყნებული WGS 84 მნიშვნელობები ცოდნიდან არის მოყვანილი და გამოყვანასთან შედარებული. ყოველი მათგანი ემთხვევა იმ ციფრებამდე, რომლებსაც განმსაზღვრელი დოკუმენტი იძლევა:

| constant | published | derived | difference |
|---|---|---|---|
| `a` | 6378137.0 | 6378137.0 | 0.0 |
| `1/f` | 298.257223563 | 298.257223563 | 0.0 |
| `b` | 6356752.314245 | 6356752.314245179 | 1.797e-07 |
| `e2` | 0.00669437999014 | 0.006694379990141317 | 1.318e-15 |
| `a*a/b` | 6399593.6258 | 6399593.625758493 | 4.151e-05 |

ორი reference წერტილი ცხრილიდან კი არა, განსაზღვრებიდან მოდის, და იმავე დეკლარირებული region-ით არის გამოთვლილი, როგორც ყოველი სხვა რიცხვი აქ: `(phi, lambda, h) = (0, 0, 0)` იძლევა ECEF `(a, 0, 0)`-ს ზუსტად, ხოლო `(90 deg, 0, 0)` — `(0, 0, b)`-ს ზუსტად.

## Representation-ის არჩევანი, რომელიც ზუსტ პასუხს შესაძლებელს ხდის

`sin(phi)` ტრანსცენდენტულია ყოველი rational `phi`-სთვის `0`-ის გარდა, ასე რომ კუთხეებად მოცემულ latitude-ების sample-ს ზუსტი არითმეტიკა უკან არ უდგას. ამიტომ geodetic encoding დეკლარირებულია **ტრიგონომეტრიული ფორმით**, ხოლო ყოველი sample latitude და longitude პითაგორული სამეულიდან იგება:

```text
geodetic, angle form           (phi, lambda, h)
geodetic, trigonometric form   (sin phi, cos phi, sin lambda, cos lambda, h)

cos = (m*m - n*n) / (m*m + n*n)      sin = 2*m*n / (m*m + n*n)
```

ასე რომ `sin*sin + cos*cos == 1` ზუსტად. მაშინ forward map-ის ყოველი სიდიდე ძევს `Q(sqrt(W))`-ში, სადაც `W = 1 - e2 sin^2 phi` არის rational — რაციონალურთა ერთი კვადრატული გაფართოება, ჩაკეტილი ოთხივე ოპერაციის მიმართ. **ამ ექსპერიმენტის ზუსტი მხარე არის ზუსტი არითმეტიკა და არა მაღალი სიზუსტის მცურავმძიმიანი.** ტრიგონომეტრიული ფორმა დეკლარირებული არჩევანია; ის მესამე representation-ია თამაშში და შეზღუდვებში ხელახლა არის დასახელებული.

Sample არის `24` ხელით შერჩეული წერტილი `6` დეკლარირებულ რეჟიმში: `6` საშუალო განედზე, `5` პოლუსთან ახლოს, `5` ეკვატორთან ახლოს, `4` დეგენერატული (ზუსტი პოლუსი და ზუსტი ეკვატორი), `2` მცირე სიმაღლეზე, `2` `lambda = 0`-ზე. რეჟიმი ასახელებს, რატომ შეირჩა წერტილი, და თვისებებს არ ყოფს — `5` წერტილი ნულოვან სიმაღლეზე ზის და `5` საწყის მერიდიანზე. სიმაღლეები `-400`-დან `35786000` მეტრამდე მიდის.

## Multicore

Repository-ის პოლიტიკა არის multicore ნაგულისხმევად დაკვირვებული გადაწყვეტილებით, და აქ დაკვირვება ამბობს: sequential.

```text
cores observed                    16
workers the policy would raise    15      (one core of headroom)
sample                            24 points
sequential                        0.054 s        0.00225 s per point
raising a pool                    2.20 s         before any work is done
break-even                        1048 points
chosen path                       sequential
sequential and parallel agree     yes
```
**ეს სამი რიცხვი module-ის ლიტერალია და არა ამ გაშვების დაკვირვება**, და review-მ ისინი იმავე უქმ მანქანაზე
ხელახლა დააკვირდა. `POINT_SECONDS = 0.00225` და `POOL_STARTUP_SECONDS = 2.20` გამოცხადებული მუდმივებია;
sequential-ის ჯამი და break-even მათზე არითმეტიკაა. ხელახლა დაკვირვებული: `0.001265` წმ წერტილზე, ანუ
`1.8`-ჯერ ნაკლები გამოცხადებულზე, pool-ის ამოშვება `2.267` წმ, და break-even `1920` წერტილი და არა `1048`.
გადაწყვეტილება ორივე შემთხვევაში უცვლელია — `24` წერტილი ორივე break-even-ზე ბევრად ქვემოთაა და
`test_sequential_and_parallel_agree` გადის — მაგრამ card-ის სტანდარტია, რომ ყოველი რიცხვი გაშვებიდან მოდის,
და ეს სამი არ მოდიოდა.


Break-even არჩეული ზღვარი არ არის: pool-ს თავისი გაშვება უჯდება, შემდეგ კი სამუშაოს `15`-ჯერ უფრო სწრაფად ასრულებს, ასე რომ მისი აშენება ზუსტად მაშინ ღირს, როცა `n * t > startup + n * t / 15`, რაც დაკვირვებულ ტემპებზე `1048` წერტილია. Sample არის `24`. Parallel გზა იმპლემენტირებულია, `6` წერტილზე `2` worker-ით test-ითაა გავარჯიშებული და იდენტურ შედეგებს იძლევა — parallelism ცვლის იმას, თუ რამდენად სწრაფად, და არასდროს იმას, რაზეც დაკვირვება ხდება.

- **Generation 1 ამათგან ვერაფერს წერს.** `63` დეკლარირებული operation-იდან `16`-ს პროექტის notation-ში შესატყვისი არ აქვს. `sin`, `cos` და `sqrt` არსებობს მხოლოდ როგორც ერთარგუმენტიანი outer ფუნქციები, რომლებიც მთელ expression-ს ახვევენ; `atan2` საერთოდ არ არსებობს და ორარგუმენტიანია. ამ პროექტის ვერცერთი world geodetic conversion-ს არ წერს, და ამ report-ის ვერცერთი რიცხვი არ უნდა წაიკითხოს ისე, თითქოს წერდეს;
- **ellipsoid დეკლარირებული არჩევანია.** WGS 84, თავისი ორი განმსაზღვრელი კონსტანტით. სხვა ellipsoid ცვლის აქ ყოველ მეტრს და არაფერს ცვლის სტრუქტურულად;
- **tolerance-ები დეკლარირებული არჩევანებია**, და თითოეული საკუთარი განსაზღვრების ადგილას ამბობს, რა იცვლება მისი გადაადგილებისას. Convergence tolerance `1e-12` რადიანი წყვეტს iteration-ის რაოდენობას და ამიტომ seam-სა და crossover-ს, და სწორედ ამიტომ ორივე `4` tolerance-ზეა გამოქვეყნებული და არა ერთზე;
- **sample ხელით არის შერჩეული** — `24` წერტილი განთავსებული იქ, სადაც კლასიკური ფორმულები ცნობილად დელიკატურია. ეს არ არის sampling design და ის ვერანაირ მტკიცებას ვერ უჭერს მხარს latitude-ების განაწილების შესახებ; ის მხარს უჭერს მტკიცებებს იმ წერტილების შესახებ, რომლებსაც შეიცავს;
- **ტრიგონომეტრიული ფორმა მესამე representation-ია**, შემოტანილი იმისთვის, რომ ზუსტი ავტორიტეტი საერთოდ არსებობდეს. Geodetic encoding-ის შესახებ ნათქვამი შედეგები ზუსტ მხარეს მის ტრიგონომეტრიულ ფორმაზეა ნათქვამი, ხოლო float მხარეს — მის კუთხურ ფორმაზე, და სექცია 4 სწორედ იმიტომ არსებობს, რომ ეს ორი ერთი და იგივე არ არის;
- **ყოველი operation ერთ ერთეულად ითვლება**, `sin`, `cos`, `sqrt` და `atan2` ჩათვლით. ეს მოდელირების არჩევანია, ხოლო სექცია 3-ის weight sweep სწორედ ის არის, რაც მას ხილულს ხდის და არა დამტვირთველს. ვერცერთი ეს რიცხვი დრო არ არის;
- **float-ის ქცევა ამ მანქანისაა.** ზუსტი rational მხარე არის ავტორიტეტი, ხოლო სექცია 4-ის ყოველი float რიცხვი არის დაკვირვება IEEE-754 double არითმეტიკაზე ამ მანქანასა და ამ SymPy-ზე;
- **ეს card ამოწმებს Region model-ის წანამძღვარს ერთ წყვილზე.** ის არ განზოგადდება engine-ზე, ის არ აჩვენებს, რომ search ამ transformation-ებიდან რომელიმეს იპოვიდა, და ის არაფერს ამბობს იმაზე, არის თუ არა decode obligation დასაფარი იმ წყვილზე, რომელიც ხელით ჯერ არავის ამოუხსნია.
